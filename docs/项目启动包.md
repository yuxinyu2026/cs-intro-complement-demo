## 二、为什么是补码（选题评估）

### 2.1 排序

| 名次 | 选题 | 理由 | 最大风险 |
|---|---|---|---|
| **1** | 补码加减法模拟器 | 深度够 + 分工天然 4 块 + **AI 输出可穷举对拍** | -128 边界、溢出判定 |
| 2 | K-Means 聚类迭代 | 视觉冲击最强，契合"AI/ML 方向" | 随机初始化，需固定种子 |
| 3 | 进程调度（FCFS/SJF/RR） | 甘特图动态强、多算法撑工作量 | 时间轴动画调试费时 |
| 4 | 页面置换（FIFO/LRU/OPT） | 分工最省心，但深度偏浅 | OPT 逻辑、输出格式不统一 |
| 5 | 进位制转换（加强版） | 最稳最快，兜底 | 易被判工作量不足 |

### 2.2 评估矩阵（1–5 分）

| 选题 | 课堂视觉 | 技术深度 | 4人可切分 | 好做程度 | AI可靠性 | 与示例重复(越低越好) | 合计 |
|---|---|---|---|---|---|---|---|
| **补码加减** | 4 | **5** | **5** | 4 | 4 | 5 | **27** |
| K-Means | **5** | 4 | 4 | 4 | 4 | 5 | 26 |
| 页面置换 | 4 | 3 | **5** | **5** | **5** | 5 | 26（深度扣分） |
| 进程调度 | 4 | 4 | **5** | 3 | 4 | 5 | 25 |
| 梯度下降 | 4 | 5 | 4 | 2 | 3 | 5 | 23 |
| 进位制 | 3 | 2 | 3 | **5** | **5** | 5 | 23 |
| 排序查找 | 4 | 2 | 4 | 5 | 5 | 4 | 24（深度硬伤） |
| ASCII/校验 | 3 | 2 | 3 | 5 | 5 | 5 | 23 |
| 图灵机 | 4 | 5 | 4 | 3 | 4 | **1** | 21 |

### 2.3 补码胜出的四条硬理由

1. **深度天然够**：原码/反码/补码/移码、求补、进位链、双符号位溢出 —— 教师翻两页就知道不是套壳计算器。
2. **可视化天生分步**：8 个位格，求补逐位翻转、加一像多米诺、溢出红闪。
3. **4 人真能拆开**：引擎 / 界面 / 渲染 / 文档，互不阻塞。
4. **AI 错了能当场抓出来**：用 Python 内建整数穷举对拍。**这一条直接对应 25% 的"识别并修正 AI 错误"考点** —— 本项目已经用它抓到 1 个真 Bug（见第六节）。

### 2.4 为什么"页面置换"排第 4（它很好但过不了深度关）

FIFO 是队列、LRU 是栈、OPT 是向后扫描，三份核心各约 50 行；教师问"技术难点在哪"答不上来。若非要选它，必须加：**Belady 异常对比曲线 + 工作集/局部性分析 + 三算法同屏对拍**。

### 6.3 过程中真抓到并修掉的 Bug（写进 AI 日志的素材）

`to_twos_complement_steps(-128, 8)` 直接崩：
**根因**：-128 的绝对值 128 需要 8 个数值位，加符号位共 9 位，超出 8 位位宽 —— 8 位下 -128 **没有原码和反码表示**，AI 的公式把最高位挤掉了。
**修法**：加最小负数特例，直接取补码 `1000 0000`，并把这个特例写成一个教学点（"补码为什么能比原码多表示一个数"）。
**意义**：只手工试 -5、-127 是发现不了的，必须靠穷举对拍 —— 这正是 25% 那一项要的东西。

### 7.2 第 2 步：把本地仓库推上去

在 `C:\Users\admin\Downloads\cs-intro-complement-demo` 里打开 PowerShell（或在 VS Code 终端），执行：

```powershell
# 把 git 加进当前会话 PATH（便携版，每次新窗口都要执行一次）
$env:Path = "C:\Users\admin\Downloads\_tools\PortableGit\cmd;" + $env:Path

# 首次提交若作者信息不对，先改成你自己的 GitHub 身份
git config user.name  "你的GitHub用户名"
git config user.email "你的GitHub邮箱"
git commit --amend --reset-author --no-edit

# 关联远程仓库并推送
git remote add origin https://github.com/<你的用户名>/cs-intro-complement-demo.git
git branch -M main
git push -u origin main
```

> 第一次 `git push` 会弹浏览器登录 GitHub（或用 Personal Access Token 当密码）。
> 如果你开了代理（机场），git 默认不走系统代理，需要单独指定：
> `git config --global http.proxy http://127.0.0.1:7890`（端口换成你机场实际的）。

### 7.3 第 3 步：加组员 + 给教师权限
