# 团队协作手册（4 人组按这个做）

> 仓库：https://github.com/yuxinyu2026/cs-intro-complement-demo
> 目标：每人独立分支开发 → 提 PR → 组长 Review 后 Merge → 留下清晰的协作记录（占 Git 30%）

---

## 一、第一次上手（每人 5 分钟）

### 1. 装 Git

下载 <https://git-scm.com/download/win>，一路 Next 默认安装即可。

验证（打开 cmd 或 PowerShell）：

```bash
git --version
```

### 2. 配置身份（只做一次）

```bash
git config --global user.name  "你的名字拼音"
git config --global user.email "你的GitHub邮箱"
```

> 名字会显示在每条 commit 上，组长的 Review 和老师的评分都看这个。

### 3. 克隆仓库

```bash
git clone https://github.com/yuxinyu2026/cs-intro-complement-demo.git
cd cs-intro-complement-demo
```

> 私有仓库需要先被组长加成 Collaborator，并接受邮件邀请。

### 4. 认证（第一次 push 时）

GitHub 不接受账号密码，用 **Personal Access Token**：

1. 打开 <https://github.com/settings/tokens/new>
2. Note 填 `my-push`，Expiration 选 90 days，勾 **`repo`**
3. Generate → 复制 `ghp_...`
4. push 时：用户名填你的 GitHub 用户名，密码粘贴这个 token

## 二、分支规范（必须遵守，否则 PR 会乱）

| 分支名 | 谁用 | 干什么 |
|---|---|---|
| `main` | 只有组长合并 | 稳定版，任何人不得直接 push |
| `docs/<名字>-<章节>` | 全员 | 文档阶段，如 `docs/li-可视化设计` |
| `feature/ui-layout` | 成员 B | 界面布局 |
| `feature/core-logic` | 组长 | 核心算法 |
| `feature/viz-anim` | 成员 C | 渲染动画 |
| `test/cases` | 成员 D | 测试用例与文档 |

```bash
git checkout -b feature/你的分支名
```

---

## 三、每日工作流（照着敲）

```bash
# 1. 切回 main 拉最新
git checkout main
git pull

# 2. 切回自己的分支并同步
git checkout feature/ui-layout
git merge main

# 3. 干活……然后提交
git add .
git commit -m "feat(ui): 完成主窗口布局与位宽切换"
git push

# 4. 去 GitHub 网页发起 Pull Request
```

---

## 四、提交信息规范（评分会看）

格式：`类型(范围): 中文简述`

| 类型 | 用途 | 例子 |
|---|---|---|
| `feat` | 新功能 | `feat(core): 实现按位加法与进位链` |
| `fix` | 修 bug | `fix(core): 修正 -128 求补越界` |
| `docs` | 文档 | `docs: 完成可视化设计章节` |
| `design` | 界面/设计 | `design(ui): 调整位格配色与间距` |
| `test` | 测试 | `test: 补充 16 位抽样对拍` |
| `chore` | 杂务 | `chore: 更新 .gitignore` |

**禁止**：`update`、`修改`、`123`、`aaa` 这类无信息量信息。

## 五、Pull Request 流程

1. 分支 push 后，GitHub 页面会出现绿色按钮 **Compare & pull request**
2. 标题写清楚做了什么（如 `feat(ui): 主窗口布局与位宽切换`）
3. 描述里写三点：
   - 改了什么
   - 怎么验证的（截图 / 运行命令）
   - 有没有遗留问题
4. 右侧 **Reviewers** 选组长
5. 组长点 **Merge pull request** → **Confirm merge**

> ⚠️ 合并方式选 **Merge commit**，**不要选 Squash**：Squash 会把你的多条 commit 压成一条，提交记录里就看不到"谁做了什么"，直接影响 Git 分。

## 六、冲突演练（D5 必做，评分明确要求"成功处理了合并冲突"）

由组长安排两人**同时修改 `main.py` 里的窗口标题或 geometry**，然后：

```bash
git checkout main
git pull
git merge feature/ui-layout
# 出现冲突：
#   <<<<<<< HEAD
#   你的版本
#   =======
#   对方版本
#   >>>>>>> feature/ui-layout
```

处理步骤：

1. 打开文件，**两人一起看**，决定保留哪段（或合并两段）
2. 删掉 `<<<<<<<`、`=======`、`>>>>>>>` 三行标记
3. 保存 → 运行程序确认没坏
4. 提交：

```bash
git add main.py
git commit -m "fix: 解决 main 与 feature/ui-layout 在窗口初始化处的冲突"
git push
```

5. **截图存档**：把带冲突标记的 VS Code 界面截一张，存 `images/conflict.png`，README 里引用它

> 绝对不要用 `git checkout --theirs` / `--ours` 整文件覆盖 —— 会把对方那一整节的代码抹掉，而且 commit 记录里能看出来。

## 七、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `Authentication failed` | 用了账号密码 | 改用 PAT（见 1.4） |
| `Updates were rejected` | 远程有你本地没有的提交 | 先 `git pull --rebase` 再 push |
| `Please tell me who you are` | 没配身份 | 执行 1.2 |
| 图片在 GitHub 上显示不出来 | 用了绝对路径 | 改成 `images/xxx.png` 相对路径 |
| `main` 上多了奇怪的 commit | 直接改 main 了 | 立即 `git revert`，以后只在分支上改 |

## 八、红线（违了直接扣分）

- ❌ 直接往 `main` push（必须走 PR）
  > 2026-11-24 已发生一次：`47103de Update team member name in README` 由组员直接推到 main。
  > 处理方式：**不回退**，该组员立刻补一次规范的分支 + PR，证明已掌握流程。
- ❌ commit 信息写成英文口语（`Update xxx` / `fix bug` / `test`）——必须是 `类型: 中文简述`
- ❌ 用 Squash 合并
- ❌ 整文件覆盖式解决冲突
- ❌ 提交 `__pycache__`、`.exe`、`.venv`
- ❌ 三个人改同一个文件同一段却不沟通

---

## 九、提交前自查（每次 push 前 10 秒）

```bash
git branch --show-current     # 不是 main 才继续
git status                    # 确认没有多余文件（.exe / __pycache__）
git log --oneline -3          # 看最近 3 条 commit 信息格式对不对
```

三条都过再 push。
